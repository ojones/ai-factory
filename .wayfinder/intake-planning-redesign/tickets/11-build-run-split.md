## Question

Behaviour-preserving: break `build_run.py` (2617 lines) into the `build_run/` domain folder, one file per responsibility along STEP 4.1 to 4.14 (for example prepare, coder loop, precheck, review, push, ci and deploy, pipeline diagnosis, tester, retest, rollback, release gate, outcome and report), each with its own focused tests moved out of the 1359-line `build_run_test.py`. The `BuildRun` orchestration keeps only sequencing. Planning (`plan_change`) stays in place until the planning-process ticket moves it out. Existing tests must pass unchanged in meaning before and after.

## Added context

Pure refactor, its own commits, no new behaviour; if a test of a seam is missing, add it before moving the code under it (characterize first). The domain's public interface (run a child) and its inputs (the child body and marker) are written into `docs/orchestrator-map.md`. Largest mechanical change; split across more than one session if needed, in small green commits.

**Target files in `build_run/`** (decided in ticket 04; this ticket owns the exact function-by-function mapping, tests first where a seam has none): `start_build.py` (the gate that starts a run for a child, from `update_intake.start`), `read_child.py` (the child's body and marker), `prepare_run.py` (setup, template files, secret wiring, daily cap, capacity wait, model check), `run.py` (sequencing only), `write_code.py` (coder round, protected-file check, precheck), `review_code.py` (review context, banded findings, verdict, flag and suppression findings), `ship_code.py` (push, CI and deploy wait, pipeline diagnosis), `test_deployed_app.py` (tester round, helper reconcile, `test_impact`, retest), `track_progress.py` (scoreboard, stuck detection, round records), `gate_release.py` (the release gate and Preview Token), `rollback_deploy.py` (regression decision and the CI rollback). The Agent runtime is already in `shared/agent_runner`; the run summary and finalize go to `retrospective/`; the watchdog and `release` go to `flag_lifecycle/`. Move each file's tests out of the 1,359-line `build_run_test.py`.

## Resolution (2026-10-19)

`ruff check` clean, 613 tests OK (3 skipped), `boundary_test` and `flow_spec_test` pass, every module under `orchestrator/` imports. Not committed. **Not run live**: `build-run.yml` now runs `PYTHONPATH=factory/orchestrator python -m build_run.run run` and `update-app-intake.yml` runs `python -m build_run.start_build start`; the first Update App Intake after the push is the proof, together with ticket 10's finalize and ticket 08's flag steps.

**What moved.** `build_run.py` (1,727 lines) is the `build_run/` folder, generated by a script that moved each function and method unchanged and qualified every cross-file reference (no behaviour edits):
- `run.py` (237 lines: `__init__`, `gh`, `git`, `head`, `check_limits`, `record_spend` and `run`, the sequencing; the entry), `prepare_run.py` (STEP 4.1), `agent_calls.py`, `write_code.py` (4.3, 4.4), `review_code.py` (4.5 and the review context, banded findings, verdict, flag and suppression findings), `ship_code.py` (4.6 to 4.8), `verify_deployed_app.py` (4.9, 4.10), `gate_release.py` (4.12, 4.13 and the glue to Flag Lifecycle), `track_progress.py` (Report state, scoreboard, stuck detection), `suggestions.py`, `endings.py`, `read_child.py`, `plan_change.py` (planning stays in the run until ticket 13), `start_build.py` (from `update_intake.py`, which is gone) and `ui_check.py` (moved in with its test).
- **Design note, honestly:** `BuildRun` is still one object. Its steps are mixin classes (`PrepareRun`, `WriteCode`, `ReviewCode`, `ShipCode`, `VerifyDeployedApp`, `ReleaseStep`, ...) over the run's shared state, so the split is by file and responsibility and the pure functions are now importable alone, but the methods are not yet independent modules. Turning a step into a function with explicit inputs is the next depth, and it is cheapest where a step has two callers; I did not do it here because this ticket is behaviour-preserving.
- **Names that differ from ticket 04:** `verify_deployed_app.py` instead of `test_deployed_app.py` (a `test_` file name breaks the repo's own style rule); no `rollback_deploy.py` because rollback is `shared/rollback.py` since ticket 10. `release` and the watchdog stay thin glue in `gate_release.py` over `flag_lifecycle/`, because the tests and the run patch those seams.
- **Tests.** The 1,454-line `build_run_test.py` and `update_intake_test.py` are split by class into the file that tests the code (`build_run/*_test.py`, plus `shared/prompts_test.py`, `preview_token_test.py`, `agent_usage_test.py`, `spend_budget_test.py`, `agent_process_test.py`, `retrospective/run_summary_test.py`, `agent_spend_test.py`). Test counts are unchanged except the ones I merged away (613 before and after).
- **Fixed on the way:** `production_feedback.py` imported `build_run` for `sh` and `log` (now `shared`), and the scripts under `agents/` (`smoke`, `smoke-tester`, `smoke-coder`, `replay`) still imported names that earlier tickets had moved out of `build_run`; they now import from `build_run.*` and `shared`. Only `smoke_tester_test` exercises them, so run each once before relying on it.
- Docs: `docs/orchestrator-map.md` (Build Run row), `docs/flow-spec.md` step table and the workflow comments.

**Left for later.** `BuildRun` still parses its own inputs inside `setup` (ticket 12 moves that to `read_child` and refuses an unplanned child); `plan_change.py` and `update_intake`-era `planned` outcome go in ticket 13; the mixins' state could be passed explicitly.
