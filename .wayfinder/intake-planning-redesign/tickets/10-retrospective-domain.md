`ruff check` clean, 613 tests OK (3 skipped), `boundary_test` and `flow_spec_test` pass. Not committed. **Not run live**: `build-run.yml`, `factory-run.yml` and `factory-checks.yml` now call `python -m retrospective.finalize` / `retrospective.run_retrospective` with `PYTHONPATH`, so the first run after the push is the proof (finalize, the retrospective, a factory run, an auto-merge check).

**Moved first, behaviour unchanged** (suite green before the advance rules changed):
- **`retrospective/`** from `retrospective.py` (873 lines, split by step and generated by a script that qualifies every cross-file reference): `run_retrospective.py` (entry and sequencing, `lesson` and `auto-merge-check` commands), `run_facts.py`, `lesson_records.py`, `minor_findings.py`, `improvement_issues.py`, `agent_run.py` (the Agent in isolation and the allowed paths), `learning_pr.py`, `story_report.py`, `tracker.py` (finding duplicates, counting sightings). No file imports a later one; `retrospective_test.py` is split the same way.
- **From `build_run.py`:** `finalize.py`, `run_summary.py` (`render_summary`), `app_state.py` (with `appstate.py`'s renderers and `update_state_issues`), `run_audit.py` (was `audit.py`), `close_child.py` (`finish_update_intake`). `build_run.py` no longer has `finalize` (2,130 to about 1,780 lines).
- **To `shared/`, because both Build Run and Retrospective use them:** `rollback.py` (`rollback_decision`, `rollback_deploy`, `rollback_failed_run`; ticket 11 does not need to split it), `spend_ledger.py` (`ledger_line`, `ledger_total`, `record_spend_in_ledger`), `prompts.py` (`load_prompt`, `render`), `outcomes.TITLES`.
- **`try_fix/fix_request.py`** is `fixrequest.py` moved whole (with the retry marker `fix_meta` from `update_intake.py`) so the Retrospective can import `try_fix`; ticket 15 builds the domain. Edges now: `retrospective` imports `try_fix`, `request` and `flag_lifecycle`, never `build_run`; `build_run` imports `try_fix` (retry state). `update_intake.py` keeps only `start`, which moves with the Build Run in ticket 12.

**Changed:**
- **Advance by blockers (STEP 6.3, INV-23).** `close_child.advance` finds the closed child's parent (`parent_of`), lists its sub-issues and starts the one that is open, waiting and has every blocker closed, lowest number first. Nothing starts while another child is in flight (`proceed-with-change`) **or stalled** (open with neither label: its run stopped), which is how a failed child blocks its siblings until it is retried or closed. The marker's `depends_on` is gone (the blockers are the only record of order).
- **The parent closes with its last child (STEP 6.4).** When every sub-issue is closed, the Orchestrator closes the parent with a comment; GitHub never does.
- **The cause is named once (STEP 6.2).** `cause.name_cause(facts, result)` gives `{category, route}` (`app`, `factory` or `info`) from the Agent's category, or inferred from the ending when the Agent did not run (ran out of budget: `model_limit`; regression or failed checks: `regression`; nothing: `info`). It is written to `retrospective-cause.json`, shown in the story report, and uses the same rules as `file_fix_request`. It files nothing new: the fix child that consumes it is ticket 15; today's fix request and app retry run unchanged.
- **STEP 6.6 (ongoing signals)** has no code of its own: it is the loop back to STEP 1.3 through the Request, Maintenance and Monitoring domains, which already file their Update App Intakes with the PAT. Said in the orchestrator map instead of adding an empty hook.
- Tests: `close_child_test.py` (gating by blockers, one at a time, stalled child holds siblings, parent closes only on the last, no parent does nothing, finishing never raises), `cause_test.py`, and `shared/fake_issues.py` supports the new calls. INV-17, 20, 23, 45 reworked for the new locations.

**Left for later.** The `planned` outcome mirrors (INV-24, 25, 26) stay until ticket 13; the Retrospective still files a fix request and an app retry, not a fix child (15); `update_intake.start` and `identify_intake` move with the Build Run (11, 12).
